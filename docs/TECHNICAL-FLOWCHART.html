5. Tools, services and data boundaries

Vercel frontend/control plane

Public URL: https://eletters.vercel.app

Python entry: app.py → letter_registry.api:app; vercel.json sets 60-second maximum duration for app.py.

Public Vercel deployment must not hold private Google Drive upload credentials.

Oracle VPS API and worker

FastAPI/Uvicorn listens on loopback 127.0.0.1:8877.

Public Funnel :10001 forwards to this local API. API authorization must remain independent of network origin.

GitHub is source of truth; VPS runtime must be checked separately before runtime changes.

Supabase Auth / Postgres / RLS

Identity is separate from archive membership. Membership/roles and RLS/API checks constrain record access.

Stores structured metadata, provenance, processing state/jobs and search projection.

Private Google Drive

Stores original files as source evidence.

OCR, AI fields, translations, titles and summaries are derived representations and must not overwrite originals.

AI gateway

Supabase Edge Function: gemini-ai-gateway.

Handles AI-assisted document understanding; keep provider credentials server-side and validate extracted fields.

Search/index

Keyword/full-text search with title, metadata, OCR text and fuzzy matching is documented as active.

Semantic/vector search was not active in the reviewed state; embedding stage was not provisioned and letter_chunks was empty.

WhatsApp intake/delivery

Existing Hermes bridge: bridge.js --port 3000; DLR intake unit files observed.

Approved group allowlist, protected staging, provenance and duplicate handling are required. Do not start a second WhatsApp client.

Gmail SMTP / outbox

Delivery service and timer files observed. Treat queue state and delivery result as separate from archive record state.

Credentials must remain in protected runtime configuration, never in Git or logs.

OCR and translation

Prefer native PDF text; use Hindi/English OCR for scans. Translation is shown as an optional separate branch.

Automatic translation worker/table/fields were not verified as deployed. Label original, OCR and translation distinctly.

6. Decision conditions and failure paths

Source and target language sameSkip translation and mark not required.Avoid unnecessary transformation.
Target language differsCreate separate translation with language metadata.Never replace original/source text.
Critical field mismatch or low confidenceHuman review before verified status.Official references and dates must be reliable.
Database write failureLog safe error, retry idempotently, avoid duplicates.Prevent silent loss or duplicate records.
Delivery failureRetain status/attempt history; retry by configured policy.Queued delivery is not confirmed delivery.

7. Documentation update rule

Whenever a code or infrastructure change modifies a route, URL, port, service/timer, integration, tool/provider, processing branch, translation behavior, storage boundary, security exposure or failure condition, update this flowchart and docs/INFORMATION-FLOW-AND-DEPLOYMENT.md in the same change. Update README and current-state/brain handoff records when architecture or operating status changes. Mark observations as verified, documented or unconfirmed; never guess service ownership or claim a feature is live without evidence.

  • Re-check source/config and tests for code-path changes.
  • For live VPS claims, perform a separate read-only runtime check before documenting them.
  • Do not include secrets, private Tailscale hostnames, real letters, private Drive identifiers or credentials.
  • Do not deploy, restart services, change ports/Funnel/DNS, migrate data or run backup/restore as part of documentation-only updates.
